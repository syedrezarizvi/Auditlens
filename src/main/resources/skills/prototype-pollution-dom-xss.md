---
name: prototype-pollution-dom-xss
description: Review client-side JavaScript and DOM sinks for prototype pollution and DOM-based XSS using static analysis of captured JS, plus harmless URL-fragment probes.
---
1. Static review first (no requests needed): get_message on the main app JS bundle(s); search_traffic/extract for dangerous sinks: `innerHTML`, `outerHTML`, `document.write`, `eval(`, `Function(`, `setTimeout(` with string args, `location.hash`/`location.search` read directly into a sink, `postMessage` handlers without origin checks, `__proto__`/`constructor.prototype` assignment patterns, `merge`/`extend`/`defaultsDeep`-style deep-merge utilities fed with user input (prototype pollution sinks).
2. DOM XSS via fragment/query: if a sink reads `location.hash` or a query parameter and writes it into the DOM unescaped, this is testable by constructing (not auto-navigating to) a URL with a harmless marker in that position and asking the pentester to open it manually in a browser, OR by using get_message/extract to show the exact source->sink flow as static evidence — you cannot execute JavaScript yourself, so report the flow rather than claiming confirmed execution.
3. Prototype pollution probe (safe): if a JSON-accepting endpoint deep-merges request bodies into server state, a single harmless key like `"__proto__": {"ollamaatTest": true}` can reveal pollution if a later unrelated response/object unexpectedly carries that property — only do this once per endpoint and avoid keys that could alter real behaviour (no `isAdmin`, `role`, etc. in this probe).
4. Never craft or deliver an actual exploit (no auto-opening URLs, no injected `<script>` execution against the live app). Your job is to identify the sink/source pair and let the pentester confirm interactively.
5. add_finding (confidence tentative unless the source->sink flow is unambiguous in the JS) with the exact code snippet/line as evidence and a client-side remediation (sanitize before DOM write, use textContent, avoid eval-family, freeze prototypes / use Map instead of plain objects for merges).
